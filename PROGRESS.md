Ответ из другого блока — «Блок A · …». Отказ прежнего тапа, чью полосу уже сменили или закрыли, не теряется — строкой до «×»; ошибка на полосе при новом тапе тоже остаётся строкой. Успех уходит сам, предупреждение и ошибка — до «×». После «Отменить» фокус — на заголовок новой полосы, после «×» — туда, откуда пришли. Полоса — fixed вне контейнера списка (container query делает контейнер опорой для fixed), под списком — отступ, пока полоса видна.
- Строка со сменённым статусом остаётся под фильтром статуса до смены фильтра.
- Таблица `<table>` с явными ролями; вид — container query: ≥ 1000 — 8 колонок (≥ 1080 — отделка и «Обновлено» шире, строка в одну линию), 720–999 — без «Обновлено» (оно в раскрытой строке; колонка нулевой ширины, а не `display: none` — иначе colspan раскрытия добавил бы колонку), < 720 — карточка в две строки. Окно 1024 с меню — уже карточки.
- Карточка (телефон): отделка блока («как в блоке») не повторяется на каждой — видна только своя отделка квартиры; «обновлено · имя» — в раскрытии. Поиск по номеру — снаружи, рядом с «Фильтры · N» (отступление от «Решаю сам»: найти квартиру — самое частое действие); панель раскрывается на месте.
- Порция 200 строк + «Показать ещё 200» (фокус — на первую новую строку); фильтр — отложенный (`useDeferredValue`); числа — с разрядами (и на пилюлях). Этаж «от > до» не меняется местами — пустой список и «Сбросить фильтры». Включённый чип, которого больше нет в блоке, остаётся, чтобы его можно было снять.
- Пустой ответ чтения при `unitCount > 0` — «В блоке больше нет квартир — список удалили» + «Обновить страницу» (и один автоматический `router.refresh()`), а не «Ничего не найдено».
- Цвета плашки — тоны `Badge` (ok · amber · bad), общий `UnitStatusBadge` с журналом. Новые токены: `--row-alt` (зебра), `--toast-shadow`, `--opacity-busy`.
- «Обновлено …» — как `fRel` мокапа, по Ташкенту; будущее → «только что»; неверное время — разбор отказывает (`parseUnitRecord`), вывод — `null`. Форматтеры даты — один раз на часовой пояс.
- Сохранение стояков и генератор — через `settle` (обрыв связи — «нет связи», а не экран ошибки); стояки не ждут перечитывания внутри перехода (иначе навигация стояла бы на 5000 строк) и до нового чтения показывают сохранённое.
- Стенд: DEMO по умолчанию как сид; сценарии `?demo=variety | big | fail | conflict | empty` через `.bind`, переключатель блоков их сохраняет. DEMO не меняется — второй тап той же квартиры на стенде даёт ложное «в базе было …» (в облаке база ответит верно; проверяет юнит `statusOutcome`).
- Lighthouse на этом экране не меряется (кабинет за входом); поиск в блоке на 5000 — e2e записывает время.

**Решаю сам, если не возразишь** (шаг 12, «реши сам», отменяется одной фразой):
- Выделение — галочка в строке и «Выбрать все N по фильтру»; панель снизу «Выбрано N: Статус · Цена · Отделка · Удалить» (менеджеру — только «Статус»). «Отменить» 5 с и после массовой смены: каждой квартире — её прежний статус.
- Фильтры: статус — пилюли со счётчиками, как «Заявки»; подъезд и комнаты — чипы; этаж «от — до»; поиск по номеру. На 390 — пилюли лентой, остальное — под кнопкой «Фильтры». Порядок — по номеру естественно (2 < 10 < 12А).
- Генератор: «квартир на этаже» — одно число, «В подъездах по-разному» раскрывает поле на подъезд; итог «180 квартир · № 1–180» с разбивкой по подъездам; создание — одной функцией базы в одной транзакции, второй раз на блок со списком база откажет; цель приёмки — < 1 мин.
- Стояки отдельно не хранятся: у готового блока строки стояков собираются из планировок квартир (подряд идущие этажи одной позиции с одной планировкой); сохранение меняет планировку только попавшим квартирам (`riserChanges`). Одна правда — `units.layout_id`.
- Журнал: генерация — одна запись «Создан список: 180 квартир, № 1–180»; массовая правка — одна запись на действие «Статус свободна → бронь · № 41, 42, 43», а не 180 строк; одиночная — как сейчас.
- Тег ЖК: публичных страниц ЖК ещё нет (фаза 3) — завожу `lib/cache` с тегом ЖК и вызываю его из всех действий, которые меняют ЖК (и из действий шага 11); страницы фазы 3 подпишутся на него.
- Другой сотрудник поменял статус — список перечитывается при возврате на вкладку; в строке «обновлено 5 мин назад · имя».
- Отделка квартиры пустая — показывается отделка блока серым «как в блоке». Цена у брони и проданной остаётся в кабинете (серым), сайту не отдаётся (решение шага 4). CSV квартир — фаза 3 (перед удалением ЖК).

- Состояние клиента над переключателем блоков переживает смену `?blok=` (страница не пересоздаётся) — провайдеры вкладки «Квартиры» стоят там (`UnitsNoticeProvider`, `UnitsBarProvider`).
- Компилятор React (правила `react-hooks/refs`, `immutability`) не даёт передавать ref пропсом и менять его в дочернем: изменяемое состояние вне рендера — объект с методами в `useState(() => new …)` (`PausableTimer`, `FocusMemory`).
- e2e: `page.clock.install()` — часы идут и сами, между шагами теста; точные границы таймеров (4,9 / 5,0 с) проверять юнитом на `vi.useFakeTimers`. Playwright перед каждым прогоном чистит `test-results` — скриншоты для `docs/design/` снимать одним прогоном.
- В plpgsql не называть переменные как колонки квартир (`number`, `status`, `floor`, `position`, `price`, `layout_id`…): `#variable_conflict error` по умолчанию.
- Уникальность названия блока — `deferrable initially immediate`; `save_complex_blocks` откладывает её до конца цикла (`set constraints … deferred` / `immediate`). `on conflict` по этому ключу работать не будет — он и не нужен.
