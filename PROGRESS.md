- Правила: «осталось N» не показываем, если тип есть в доступной планировке блока без списка квартир (число неизвестно). Квартира без цены — «цена по запросу», а «цена от» типа берётся у планировки. Цена есть только у свободных квартир; у брони и проданных — нет.
- Квартира ссылается только на планировку своего блока (составной ключ): иначе «осталось N» считалось бы в чужом ЖК.
- Тесты базы против облака: те же `tests/db` через `pg`; файл — одна транзакция с точками сохранения и откатом в конце (в облаке ничего не остаётся), внутри неё контент облака временно убирается; файлы — по одному. Перед прогоном проверяется, что в облаке все миграции. DEMO-тест в облаке пропускается — DEMO проверяет сама `npm run demo:seed`.
- Генератор нумерует сквозняком: подъезд за подъездом, снизу вверх, по позициям; другой порядок застройщика — правкой номеров после генерации. Предел — 5000 квартир на блок, остальные пределы совпадают с ограничениями таблиц.
- DEMO: пометка — префикс `demo-` в slug застройщика и ЖК; SQL — `supabase/demo/seed.sql` и `remove.sql`; команды `npm run demo:seed` (пересоздать) и `npm run demo:remove` (удалить) через `pg` и `SUPABASE_DB_URL`. Сид и удаление в журнал не пишут (флаг `vodiy.skip_audit`), удаление чистит и журнал правок DEMO. Настоящий ЖК у DEMO-застройщика останавливает удаление. Свободные квартиры — ровно как в «Остатках по ЖК» мокапа.
- Тип дома и паркинг — наборы значений словаря мокапа (монолит / кирпич / каркасный; подземная / наземная / обе), а не свободный текст. Названия сданных объектов застройщика — на двух языках.
- Стояки: общий стояк (все подъезды) + стояк подъезда, который его уточняет; пересекаться по этажам нельзя только стоякам одного уровня. Сохранение стояков у готового блока меняет планировку только у квартир, которые в них попали.
- Анимации кабинета — как в оболочке фазы 0: появление и наведение ≤ 200 мс, без подсветки за курсором и stagger в списках.

## Заметки для разработки
- После добавления нового CSS-файла в `app/globals.css` перезапускать `npm run dev` (Turbopack не подхватывает новые `@import`).
- Мокап локально: `npm run mockup:serve` → http://localhost:4599/project/Main.dc.html; переснять: `npm run mockup:capture` (нужен запущенный сервер мокапа).
- Документация Next.js 16 — в `node_modules/next/dist/docs/` (API отличаются от прежних версий: `proxy.ts`, `cacheComponents`, `next/root-params`).
- Текущее время на сервере (`new Date()`) при `cacheComponents` — только после `await io()` (`next/cache`) внутри `<Suspense>`, иначе сборка падает. Пример — заголовок Главной кабинета.
- Появление первого экрана (hero, карточки) — с `opacity: 0.01`, а не с 0: элемент с нулевой прозрачностью Chrome не берёт в LCP.
- Новая публичная страница → добавить адрес в `READY_ROUTES` (`lib/routes.ts`), иначе ссылки на неё не будут загружаться заранее.
- `NextIntlClientProvider` сейчас отдаёт в браузер все сообщения (и тексты кабинета — на публичных страницах). В фазе 3 передавать только нужные разделы — меньше HTML.
- Lighthouse mobile: LCP на сайте 3,0 с (симуляция 4G) — для фазы 3 нужен < 2,5 с (PLAN 3а): шрифты и критический CSS первого экрана.
- Lighthouse: `npx -y lighthouse@12 http://localhost:3010/uz --only-categories=performance,accessibility,best-practices` из PowerShell, на прод-сборке (`npm run build && npx next start --port 3010`); Chromium от Playwright с ним не работает.
- Тесты базы: `npx vitest run --project db` (PGlite, ~3 с). Заглушка Supabase — `tests/db/supabase-shim.sql`: права по умолчанию как в облаке (всё открыто ролям API), поэтому каждая миграция обязана сама делать `revoke` и нужные `grant`. Хелперы прав — `private.staff_role()`, `private.has_role(...)`; в политиках вызывать через `(select …)`, чтобы считалось один раз на запрос.
- Проверки домена и `check` пропускают `null`: условие с отсутствующим ключом jsonb заворачивать в `coalesce(…, false)`.
- Команды облака: `npm run db:push` (`-- --dry-run` — только показать), `npm run test:db:remote`, `npm run demo:seed` / `demo:remove` — все читают `SUPABASE_DB_URL` из `.env.local`; `supabase login`/`link` не нужны.
- `@electric-sql/pglite-socket` 0.2.11 (временный Postgres-сервер из PGlite) ломает протокол после ошибки в запросе с параметрами — для проверки путей ошибок не годится.
- Dev и прод-сервер одновременно: dev — `.next/dev`, прод — `.next`. Перед новым `next start` остановить старый: иначе он отдаёт старый манифест и чанки 404/500.
- Фото: файл в бакете `media` — `complexes/<id ЖК>/<uuid>.jpg` или `developers/<id>/<uuid>.png` (`lib/media/path.ts` = `private.is_media_path`, тест сверяет). Строки `media_assets` при удалении ЖК удаляются каскадом, а файлы — нет: окончательное удаление ЖК (фаза 3, pg_cron) должно удалять и папку ЖК через Storage API.
- Кабинет: оболочка `app/admin/layout` статичная и уходит сразу, поэтому `redirect()` из `(cabinet)/layout` приходит потоком (200 + `NEXT_REDIRECT` в теле, браузер переходит сам), даже с `instant = false`. Настоящий 307 на вход даёт `proxy.ts` (нет cookie сессии, или продакшен без ключей). Данных кабинета в таком ответе нет — layout бросает редирект до детей.
- Каждая страница кабинета читает сессию сама (`requireViewer` / `requireSection`) и объявляет `export const instant = false` — как и `(cabinet)/layout.tsx`: `false` у layout на страницу не распространяется, без него в разработке ошибка «uncached data … connection() outside of <Suspense>».
- В облаке прямой `delete from storage.objects` без флага `storage.allow_delete_query` запрещён триггером Storage (так удаляет только сам сервис) — тест удаления ставит флаг; в коде удалять файлы только через `supabase.storage.remove()`.
