## 6A. База статистики
1. Миграция: `events` — столбцы `medium`, `content` (utm_medium и utm_content первого захода, тот же фильтр `[A-Za-z0-9._-]{1,60}`), тип `layout_view`; `track_events` принимает их (старая сигнатура уходит одной миграцией). Браузер: `medium` и `content` — из `leadSource()`, `layout_view` — раздел «Планировки» ЖК на экране ≥ 1 с, раз за визит на ЖК.
2. Функция `site_stats(p_from date, p_to date)` — только руководитель, дни по Asia/Tashkent, период ≤ 400 дней (хранение). Отдаёт: итоги — посетители (уникальные `visitor_id`), визиты (`session_id`), просмотры (`page_view`), заявки (таблица `leads` по `created_at`), конверсия, «Показали телефон / Telegram» (посетители с `phone_click` / `telegram_click`); то же за прошлый период той же длины (сегодня — вчера до того же часа); ряд по дням (сегодня — по часам) для графика; источники (сырые `source`, подписи — в `lib/stats`), устройства, язык, типы заявок; топ ЖК (просмотры `complex_view`, заявки по `complex_id`, конверсия) и топ застройщиков (через ЖК); креативы (посетители по `content`, заявки по `source->>'utm_content'`); путь посетителя (посетители → открыли ЖК → смотрели планировки → телефон / Telegram → заявка). Индекс `events (type, at)`, если план запроса попросит. Свёрток по дням не делаем: на 10–15 ЖК событий мало — вернуться, если `site_stats` за 30 дней дольше 1 с.
3. DEMO-события: `scripts/demoStats.mjs` в `demo:seed` — 60 дней посещений (источники, устройства, языки, креативы, ЖК мокапа), посетители с id из DEMO-диапазона, `demo:remove` удаляет их. Заявки статистики — DEMO-заявки сида.
Тесты: `tests/db/site-stats.test.ts` — набор событий и заявок вручную, ответ функции = числа, посчитанные в тесте (приёмка PLAN «цифры совпадают с SQL»); граница суток по Ташкенту (23:59 / 00:01), визит после 30 мин — новый, событие без посетителя кабинета — не в счёт; `access-matrix` — менеджер и видеограф получают отказ. Юниты `lib/stats` (подписи источников, проценты, дельты, «нет данных за прошлый период»).
**Готово:** db:push, тесты базы локально и в облаке, второй агент по миграции, demo:seed в облаке.

## Решения (строки — в `docs/design-decisions.md`)
- Источник посетителя — первый заход (как у заявок); прямые заходы — `source` пуст. Подписи (Instagram, Telegram, Google, Facebook, Прямые заходы, Другие) — в `lib/stats`, не в базе.
- «Показали телефон / Telegram» и воронка — уникальные посетители, не клики (иначе воронка мокапа не сходится).
- Заявки — из таблицы `leads`, не из события `lead_sent`: заявка из Telegram-бота и с отключёнными cookie тоже заявка. Конверсия = заявки / посетители (мокап); ЖК — заявки / просмотры ЖК (мокап).
- Топ застройщиков — переключателем в панели «Популярные ЖК» (PLAN требует, мокап молчит).
- Сотрудник на сайте без входа в кабинет считается посетителем — отличить его нельзя без данных человека.
- 390 — своя раскладка: KPI 2 в ряд, панели в столбец, таблицы прокручиваются внутри.

## Риски
- События пишутся с 26.10 — у первых периодов «нет данных за прошлый период» (мокап это предусматривает).
