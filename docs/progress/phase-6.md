## 6A. База статистики
1. Миграция: `events` — столбцы `medium`, `content` (utm_medium и utm_content первого захода, тот же фильтр `[A-Za-z0-9._-]{1,60}`), тип `layout_view`; `track_events` принимает их (старая сигнатура уходит одной миграцией). Браузер: `medium` и `content` — из `leadSource()`, `layout_view` — раздел «Планировки» ЖК на экране ≥ 1 с, раз за визит на ЖК.
2. Функция `site_stats(p_from date, p_to date)` — только руководитель, дни по Asia/Tashkent, период ≤ 400 дней (хранение). Отдаёт: итоги — посетители (уникальные `visitor_id`), визиты (`session_id`), просмотры (`page_view`), заявки (таблица `leads` по `created_at`), конверсия, «Показали телефон / Telegram» (посетители с `phone_click` / `telegram_click`); то же за прошлый период той же длины (сегодня — вчера до того же часа); ряд по дням (сегодня — по часам) для графика; источники (сырые `source`, подписи — в `lib/stats`), устройства, язык, типы заявок; топ ЖК (просмотры `complex_view`, заявки по `complex_id`, конверсия) и топ застройщиков (через ЖК); креативы (посетители по `content`, заявки по `source->>'utm_content'`); путь посетителя (посетители → открыли ЖК → смотрели планировки → телефон / Telegram → заявка). Индекс `events (type, at)`, если план запроса попросит. Свёрток по дням не делаем: на 10–15 ЖК событий мало — вернуться, если `site_stats` за 30 дней дольше 1 с.
3. DEMO-события: `scripts/demoStats.mjs` в `demo:seed` — 60 дней посещений (источники, устройства, языки, креативы, ЖК мокапа), посетители с id из DEMO-диапазона, `demo:remove` удаляет их. Заявки статистики — DEMO-заявки сида.
Тесты: `tests/db/site-stats.test.ts` — набор событий и заявок вручную, ответ функции = числа, посчитанные в тесте (приёмка PLAN «цифры совпадают с SQL»); граница суток по Ташкенту (23:59 / 00:01), визит после 30 мин — новый, событие без посетителя кабинета — не в счёт; `access-matrix` — менеджер и видеограф получают отказ. Юниты `lib/stats` (подписи источников, проценты, дельты, «нет данных за прошлый период»).
**Готово:** db:push, тесты базы локально и в облаке, второй агент по миграции, demo:seed в облаке.

## Первый рендер ЖК — разбор 30.10
Тестовый деплой, коммит `859a732`, DEMO, `demo-shodlik`, 412 × 823, сеть Slow 4G, новый браузер на каждый заход; сравнения вариантов — по 5 заходов, медиана, правка подмешивалась на лету. Код не менялся.
- **Lighthouse mobile (`lighthouse@12`, 3 прогона):** главная / каталог / ЖК — 99 / 99 / 94, LCP 2,0 / 1,8 / 3,1 с (симуляция на ЖК скачет 2,1–3,2 с). С реальным замедлением (`--throttling-method=devtools`), CPU ×4 — 94 / 96 / 93, LCP 2,2 / 2,2 / 2,4 с (ЖК 2,43–2,56). CLS ≤ 0,001. 72 с ноутбука на деплое не повторился: минимум главной за 9 прогонов — 92. PageSpeed Insights без ключа — 429.
- **Как читать цифры:** benchmark ноутбука ≈ 4200, средний телефон ближе к ×10, чем к ×4. Трассировка завышает: Layout при ×4 — 960 мс с подробной трассировкой и 500 мс без неё; TBT при ×10 — 1,4–1,5 с у Lighthouse и 0,35 с по Long Tasks API.
- **Куда уходит поток (×4, всего 1,33 с):** Layout 0,5 с, JS 0,28 с, стиль 0,09 с. DOM и CSS ни при чём: 2145 элементов, полный пересчёт 2296 объектов — 22–26 мс, разбор CSS — 8–10 мс. 85 % Layout — два первых прохода: текст разбирается (shaping) подменным шрифтом, затем ещё раз Manrope (грязных 1361 из 1397). По видам: shaping 55 %, раскладка 33 %, загрузка шрифтов 10 % (`FontDataManager`, есть и на пустой странице — похоже, Chrome на Windows).
- **Проверенные варианты, LCP при ×4 (без правок 2,46 с):**
  - `content-visibility: auto` на всех `.complex-section` — 2,34 с, поток −12 %. Цена: фото в разделах начинают грузиться позже (фасад «Выбрать квартиру» при прокрутке наполовину чёрный), высота этого раздела на телефоне меняется на 40 px. Прокрутка: самая длинная задача ≤ 60 мс, CLS ≤ 0,008.
  - То же только на разделах без больших фото (`#o-zhk`, `#raspolozhenie`, `#nalichie`, `#planirovki`, `#zastroyshchik`, `#dokumenty`) с `overflow-clip-margin: 48px` — 2,38 с (все 5 заходов быстрее всех 5 без правки), поток −8 %; при ×10 LCP не меняется, поток −9 %. Скриншоты 390 и 1440 чистые, кроме сдвигов на 1 px и пересчёта чертежей. Без `overflow-clip-margin` обрезаются тени карточек и лента планировок на телефоне.
  - Manrope без заранее загруженной кириллицы (`subsets: ["latin"]`) — 2,38 с на `/uz`, но на `/ru` кириллица приходит на 1,5 с позже: 0,9–1,4 с текст подменным шрифтом, CLS главной 0 → 0,0165. Не берём: цена для `/ru` больше выигрыша `/uz`.
  - Вместе (все разделы + без кириллицы) — 2,23 с, обе цены.
  - CSS: страница использует 45 % из 247 КБ, остальное — другие публичные страницы (кабинет отдельно). Вынос по маршрутам — по оценке до 20 КБ gzip, ≈ 0,1 с в лучшем случае; переделка импортов, до запуска не стоит.
- **Решение:** код не меняем. Бюджет держится (оценка ≥ 90, LCP 2,4 с при реальном замедлении), выигрыш 4–5 %, а настоящие фото сдвинут LCP сильнее: DEMO-фото первого экрана — 33 КБ.
- **Если на настоящем домене с настоящими фото LCP ЖК > 2,5 с:** сначала вес фото первого экрана, потом правило для разделов без больших фото — под `@supports (overflow-clip-margin: 1px)`, чтобы Safari (нет этого свойства и нет scroll anchoring) остался без него. Перед включением проверить якоря навигатора (`complex-page.spec`) и WebKit: это не проверялось.
- **Отдельно:** разброс даёт ответ CDN — 0,1 с при попадании в кэш края, 0,4 с мимо него; в 2 из 9 прогонов каталога — 1,3–2 с, и только в таком прогоне оценка упала до 89. Причину не разбирал.

## Решения (строки — в `docs/design-decisions.md`)
- Источник посетителя — первый заход (как у заявок); прямые заходы — `source` пуст. Подписи (Instagram, Telegram, Google, Facebook, Прямые заходы, Другие) — в `lib/stats`, не в базе.
- «Показали телефон / Telegram» и воронка — уникальные посетители, не клики (иначе воронка мокапа не сходится).
- Заявки — из таблицы `leads`, не из события `lead_sent`: заявка из Telegram-бота и с отключёнными cookie тоже заявка. Конверсия = заявки / посетители (мокап); ЖК — заявки / просмотры ЖК (мокап).
- Топ застройщиков — переключателем в панели «Популярные ЖК» (PLAN требует, мокап молчит).
- Сотрудник на сайте без входа в кабинет считается посетителем — отличить его нельзя без данных человека.
- 390 — своя раскладка: KPI 2 в ряд, панели в столбец, таблицы прокручиваются внутри.
