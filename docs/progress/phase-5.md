Мокап: кабинет — `CabVideo` (видеограф), `CabReview` (менеджер / руководитель), KPI и панель «Видеоотчёты» на `CabHome`; сайт — секция `prog` страницы ЖК (`SiteJk`, `MobJkProg`), страница видео квартиры (`SiteVideo`, `PhoneVideo`, `MobVideo`). Исходник — `docs/mockup/source/project/Main.dc.html` (кабинет 1448–1505, 1636–1658, логика 3838–3896, 4026–4104; сайт 909–931, 1202–1278) и `Mobile.dc.html` (400–418, 536–575).

## 5A. База
1. Миграция: `progress_reports` (ЖК, блок?, квартира?, месяц, `status` draft · returned · published, комментарий ru/uz, `return_note`, `youtube_id`, путь видео в Storage, автор, `published_by`, `published_at`; снимок квартиры для ссылки клиента — планировка, комнаты, площадь, этаж — `unit_id on delete set null`) и `progress_media` (фото 3–15, порядок). Права: видеограф — только свои черновики и возвращённые; менеджер и руководитель — все, публикуют функцией `publish_progress_report(id, p_checked)` (без галочки 1.2 — `vh:rule12`; 3–15 фото или видео по правилам ниже, комментарий на двух языках); статус и поля публикации — только функцией. Журнал — ветка `progress_reports` в `write_audit`.
2. Хранилище: фото — бакет `media` (`complexes/<id>/progress/<uuid>.jpg`), политики insert / delete видеографа только для своего черновика; видео — бакет `progress-video` (mp4, лимит — вопрос 1), докачка TUS. Архив и удаление ЖК чистят и его.
3. Функции сайта: `site_complex` → `progress` (опубликованные по ЖК и блокам, новые сверху), `site_unit_video(id)` — без номера квартиры, `unit_id`, цены; сотрудникам — `progress_overview()` для матрицы. Тесты: `tests/db/progress-reports.test.ts`, матрица `access-matrix` (видеограф: 0 строк заявок, клиентов, расчётов; не публикует; чужие черновики не видит; квартиры не меняет), `storage.test.ts`. DEMO-отчёты в `scripts/demo.mjs` с пометкой DEMO.
**Готово:** db:push, тесты базы локально и `access-matrix` в облаке, второй агент по миграции.

## 5C. Сайт

Без опубликованных отчётов — ни секции, ни пункта навигатора. Анимации — по два варианта под `[data-motion]`, `none` — постер.

**Готово:** `complex-progress.spec`, `unit-video.spec` на 1440 (noindex есть, номера квартиры в DOM нет).

## 5B. Кабинет видеографа
1. Раздел «Видео и ход стройки» открыт: видеограф после входа — сразу в нём, меню из одного пункта, тостов заявок нет («Отчёты видеографа»; менеджеру — «Видео и ход строительства»).
2. «Новый отчёт»: ЖК (не сданные), месяц — текущий или прошлый, блок (если их несколько), квартира необязательно (кроме проданных); фото 3–15, комментарий RU / UZ; справа «Как снимать» и «Мои отчёты» (5 последних, статусы).
3. Видео: загрузка с телефона с докачкой (`tus-js-client`, тексты обрыва и продолжения как в мокапе) или ссылка YouTube; пока видео грузится — отправить нельзя.
4. Возвращённый отчёт — с причиной, можно исправить и отправить снова.
**Готово:** `video-reporter.spec` на 1440 + ручной прогон с телефона на DEMO в облаке.

## 5D. Проверка, публикация, напоминания
1. Менеджер / руководитель: «Ждут проверки · N», ящик отчёта с галочкой 1.2 («Опубликовать» неактивна без неё) и «Вернуть видеографу» с причиной; после публикации — кэш страницы ЖК.
2. Матрица «Отчёты по ЖК · последние 6 месяцев» (ячейки: опубликован · проверка · сдан · ждём · —; бейдж «45+ дн.») — это и есть список ЖК без отчёта за месяц; «Видео для клиентов» — «Ссылка» и «Открыть»; KPI «Видео за {месяц}» и панель «Видеоотчёты» на Главной менеджера.
3. Расписание `progress` раз в сутки: напоминание в Telegram-чат тревог, если последнему отчёту ЖК > 45 дней (отметка по одному, как `20261029090000`).
**Приёмка фазы:** спеки блока, сквозной сценарий, RLS-тест, полный e2e 390 / 1440, скриншоты против `SiteJk`, `SiteVideo`, `MobJkProg`, `MobVideo`, `CabVideo`, `CabReview`; «Полировка» закрыта.

## Решения (мокап молчит или расходится с PLAN; строки — в `docs/design-decisions.md`)
- Секция на сайте — по мокапу: чипы месяцев и превью, без «последние 3 + Показать все» из PLAN (мокап выше PLAN).
- Отчёт только из фото — тот же плеер, слайд-шоу фото (кадры мокапа); отдельной галереи нет.
- Ссылка клиенту — `/video/{id отчёта}` (PLAN), не id квартиры (мокап): квартира может быть удалена, отчёт — нет. «Предыдущие месяцы» — опубликованные отчёты той же квартиры, нет своих — блока, затем ЖК (`repsForUnit` мокапа).
- «Вернуть видеографу» — статус «Возвращён» с причиной (в мокапе отчёт пропадал, и исправить его было нельзя); в Telegram видеографу не пишем — его Telegram в модели нет.
- Опубликованный отчёт не правится и не удаляется (как в мокапе); снять с публикации — руководитель, отчёт снова проходит проверку 1.2.
- 45 дней — от последнего опубликованного отчёта по ЖК в целом; строящийся ЖК без единого отчёта тоже «45+» (дыра мокапа).
- Один отчёт по ЖК или блоку за месяц; по квартире — сколько угодно.
- У каждого отчёта, и по квартире, 3–15 фото, видео по желанию (мокап: без 3 фото не отправить). Блок у отчёта есть всегда — у ЖК с одним блоком это он (мокап), «отчёт по ЖК» = отчёт по блоку.
- Комментарий черновика может быть на одном языке; при отправке на проверку — оба (мокап).
- Видео в Storage — только mp4; `.mov` с телефона — подсказка «загрузите на YouTube-канал Vodiy House».
- Трек плеера — `scaleX`, не ширина.

## Риски
- Лимит файла Supabase на бесплатном тарифе (~50 МБ) против «MP4 до 4 ГБ» мокапа — до ответа (вопрос 1) основной путь — YouTube.
- Публичный бакет: файл черновика доступен по прямому адресу, если знать uuid; принимаем, записать в «Запуск».
- Удаление отчёта и ЖК должно удалять файлы через Storage API (как архив). Блок удаляют вместе с его отчётами каскадом — их фото лежат в папке ЖК до удаления ЖК из архива (purge чистит папку), видео — бакет 5A.2 тоже добавить в purge.
- Журнал: подпись записи отчёта и статусы «На проверке / Возвращён» — в 5D (сейчас — название ЖК и сырые значения).
- `/admin/zhk/[id]/video` (видеообзор ЖК) и `/admin/video` (отчёты) — развести подписи в меню и журнале.
- Кабинетные e2e на ноутбуке могут падать из-за часов — в «Полировку».

## Вопросы к заказчику (деньги, формулы, данные)
1. Деньги: тариф Supabase Pro ради видео до 4 ГБ в Storage — или остаёмся на бесплатном (≈ 50 МБ на файл) и видео только через YouTube?
2. Формула: квартира из видео уже забронирована или продана — расчёт на странице видео показывать по её цене или «от» по планировке?
3. Данные: YouTube-канал Vodiy House уже есть (ссылка)? Первые настоящие отчёты — после «Запуска»; до них DEMO.

## Полировка (фаза 5)
- `admin.spec` «экран входа: lite → full, первый заход» на прод-сборке под нагрузкой ноутбука (сборка + прод-сервер + Playwright) дважды не набрал 150 кадров за 5 с; час назад на той же сборке ✓ — флак нагрузки, экран 5B не трогает.
- Ревью 5B, не сделано: бейдж месяца в шапке «Нового отчёта» (у AdminPanel нет места справа); поле YouTube — отдельной подписью, а не иконкой внутри «Видео»; после «Исправить» — без «Отправлено» (форма открывается новой); сервер не проверяет, что файл фото / видео есть в бакете, и `build_status` блока (форма их не предлагает).
- Видео, загруженное и убранное из формы до отправки, остаётся в `progress-video` (видеографу удалять нельзя) — уборка «сирот» при необходимости, как фото.
- Ревью 5D, не сделано: в full между кадрами баннера «Видео стройки» ~0,2 с чёрного (перекрыть ключевые кадры); в lite / none грузятся все 4 кадра (рендерить первый или lazy); сбой `site_progress_frames` кэширует каталог без кадров на часы; `blur` кадра стройки в JSON каталога (обнулить, как у фото после второго); alt кадра стройки — «Стройка · месяц», а не название ЖК; «Ждут проверки · N» не больше 50; напоминание и матрица включают черновики и DEMO-ЖК (до удаления DEMO — еженедельно в тестовую группу). Снятие и удаление отчёта в кабинете — когда появятся, звать `expireProgress`.
- `auth.spec` «cookie сессии…» на прод-сборке один раз упал («Target page closed»), повтор ✓ — флак.
- Фото, убранные из формы до отправки (или форма брошена), остаются в папке ЖК до удаления ЖК — уборка «сирот» отчётов при необходимости.
- Ревью 5C, не сделано: трек плеера — не перемотка (мокап — кнопка); калькулятор за кнопкой, а не открыт сразу (решение — design-decisions); `complex.developer` и `layoutId` уходят в браузер без использования.
- 5D: публикация и снятие отчёта — `expireComplex` и `updateTag(progressTag(id))`.
- Прод-сборка: чужой адрес видео (и ЖК — `complex-page.spec` «чужой адрес — 404» на 390) отвечает 200 со страницей «не найдено» и noindex; 404 — только у собранной заготовки. На dev — 404. Разобрать перед запуском вместе с Lighthouse.
- Dev-сервер другой сессии на :3000 не подхватил новый экспорт `lib/cache` (`progressTag is not a function`) — страница видео проверялась на прод-сборке; после перезапуска dev — прогнать `unit-video.spec` на :3000.
