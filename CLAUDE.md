# CLAUDE.md — vodiyhouse.uz · Проект-2 (v3: сайт и админка раздельно)

## Суть
Vodiy House — агентство новостроек в Фергане. Два приложения из одного репозитория (PLAN.md §10):
- `apps/site` — публичный каталог ЖК vodiyhouse.uz (/uz по умолчанию, /ru): страницы, калькулятор, формы заявок. Без кабинета, cron, service-ключа, архива и скидок; читает только опубликованное и полное.
- `apps/admin` — кабинет admin.vodiyhouse.uz (на русском): вход и роли, ЖК, квартиры, застройщики, заявки, витрина, архив, настройки, журнал, cron, Telegram-бот, кабинет мобилографа.
- `packages/shared` — общий код (деньги, форматы, квартиры, типы). `supabase/` — единственный источник схемы и миграций.
Связь приложений — только один проект Supabase и подписанный вебхук revalidate. Ни один маршрут сайта не ведёт в админку.
Шахматки нет (решение заказчика 06.10.2026) — не добавлять, даже если встретится в ТЗ или старых заметках. Наличие — простой список квартир со статусом «свободна / бронь / продана» в админке ЖК.
Стек: Next.js 16 App Router, TypeScript strict, Tailwind + shadcn/ui, Supabase, Netlify, next-intl, npm workspaces.
Правило ТЗ 1.2: в публичной части нет ни одного контакта застройщика — все кнопки связи ведут на Vodiy House.
Что читать: PROGRESS.md «Сейчас» → PLAN.md §10 и раздел текущей фазы → мокап docs/mockup/ и docs/vodiy-house-mockup.md → ТЗ. При расхождении: правило 1.2 → решения заказчика и интервью (§10) → мокап → PLAN.md → ТЗ. Старые логи docs/progress/ — только когда нужно старое решение.

## Команды
Из корня: npm run dev:site · dev:admin · lint · typecheck · test · build:site · build:admin.
В приложении (`npm run <cmd> -w apps/site`): e2e:1440 -- <спека> · e2e (полный, 390 + 1440 — только на приёмке фазы) · db:push · demo:seed.

## Как работаем
- Одна фаза, последовательно, в main. Одна сессия Claude в папке проекта. Без worktree; агенты — только чтение (аудит, ревью), код пишет одна сессия.
- **Перед каждой фазой — интервью:** аудит по теме фазы и вопросы одной пачкой (не больше 10), с рекомендацией к каждому. Код фазы не трогаем до ответов. Ответы — в PLAN.md (раздел проекта) и строкой в PROGRESS.md.
- После ответов работаем без вопросов: неясное решаем сами разумно и пишем решение в PROGRESS.md. Спрашиваем только перед необратимым: удаление данных, миграции и запись в облако, деплой, вебхуки, платежи.
- Шаг сделан = lint, typecheck, юниты затронутого модуля и одна e2e-спека на 1440 зелёные. Больше ничего.
- Блок (2–4 шага) готов = спеки блока на 1440 + ревью одним агентом в один круг (только чтение). Чиним баги, права, деньги, нарушения ТЗ и 1.2; мелочи → «Полировка» в PROGRESS.md.
- Фаза принята = тесты зелёные, полный e2e 390×844 и 1440×900 обоих приложений, скриншоты одним прогоном, «Полировка» закрыта пачкой, запись в PROGRESS.md. Lighthouse сайта — на приёмке фазы C и перед запуском.
- Нет мутационных проверок, прогонов ×10 и второго круга ревью. Исключение: миграции, права доступа и lib/calc — второй агент один раз.
- Новых стендов /dev не делать: кабинет проверяем на настоящих страницах с DEMO в облаке.
- Флак — один перезапуск; не повторился → запись в «Полировку», шаг не стоит.
- Застрял дольше 30 минут — две строки в PROGRESS.md, что пробовал, и следующий шаг плана.
- Реальные данные не выдумывать: нет данных → заглушка TODO-заказчик, работа продолжается.

## Дизайн
Мокап — ответ по умолчанию: делать как в мокапе без вопроса (структура и функции; визуал — свой лучший вариант в стиле мокапа). Для экранов админки, которых нет в мокапе, структура — описание заказчика 02.11 (PLAN.md §10).

Вопросы вне интервью — только деньги, формулы и данные ЖК, пачкой в конце шага; работу в ожидании ответа не останавливать.

## Код
- БЭМ: .block, .block__el, .block--mod. Один компонент — папка с .tsx, .css, index.ts; CSS подключается через @import в app/globals.css своего приложения. Tailwind — только раскладка и отступы.
- Токены и база — packages/shared/styles (tokens.css, base.css), общие для обоих приложений. Деньги — `@vh/shared/calc` и `@vh/shared/format`. Тексты — messages/ru.json, messages/uz.json своего приложения (админка — только ru).
- Код сайта не импортирует код админки и наоборот; общее — только через `packages/shared`. service-ключ Supabase — только в `apps/admin`.
- Имена предметные, на английском. Лимиты длины функций и файлов — предупреждение ESLint, не повод для рефакторинга до запуска.
- prettier — только по изменённым файлам, никогда по папке.

## Анимации
Два режима через <html data-motion="full|lite">, старт в lite. prefers-reduced-motion сайт не глушит (решение исполнителя 06.11.2026): none — только ?motion=none; кабинет настройку ОС слушает. Только transform и opacity.
Автоопределение уже сделано в lib/motion/ — не переписывать. Новая анимация = два CSS-варианта под [data-motion].
Ручной переключатель для тестов: ?motion=full|lite|none (none — как reduced-motion: без анимаций, первый экран — только постер).
